# ADR-005：蹬踏容錯與單次蓄刺

Status: Accepted · Date: 2026-10-07

## Context

**IMPLEMENTED，4.2.0**。4.1.0後的玩家回饋指出，蹬踏必須在短時間內精準對準頭頂，手機跳躍鍵又離左側移動區太遠，造成按下仍難以成功；長按攻擊的雙波蓄斬也不符合玩家要求的單次普通刺擊。本次明確需求是改善這兩種操作，並簡化手機按鍵的距離與顯示。

本ADR部分取代 [ADR-004](004-readable-rhythm-and-boss-capacity.md) 的 `charged` 雙波語意與協議4選擇。保留其招架節奏、Boss三階段／容量、其餘多波規則，以及 [ADR-003](003-combat-authority.md) 的固定60Hz與防守方裁決。ADR-004保存4.1.0的歷史原因，現在規格由系統文件與本ADR銜接。

## Decision

- 沿用空中重新按跳躍的輸入，建立12 combat tick的 `stompBuffer`，hitstop不消耗它。`Game.tryStomp()` 接受上方20–240px、水平差最多170px、橫掃起手／有效段或收招 `st <= 18` 的反制；成功提供最多140px水平靠近與頭頂彈跳。兩人之間有平台阻隔時拒絕輔助，避免穿越地形。
- 保留主動選擇與承諾：長按第一次跳躍不會自動蹬踏；`stomp` 每次滯空只允許一次成功，`lastStompAttackId` 拒絕同次橫掃重播。落地、受擊鎖定、緩衝逾時或競爭動作輸入清除待反制。自由行動／已確認收招可使用；跳躍可離開 `DEFLECT` 並捨棄招架窗口，起手、有效段、飲藥仍鎖定。
- 反制仍呼叫既有 `counter()`：對手承受30%自身架勢容量與35tick反彈，線上仍由防守端提出與裁決。不加入新的移動狀態、獨立反制傷害或通用吸附框架。
- 穩定ID `charged` 改顯示「蓄刺」，使用普通 `kind='pierce'`：36／6／24tick、reach210、18HP／22架勢、lunge6、單次命中，沒有 `waves` 或 `breakGuard`。仍由輕斬長按升級，持續按住可延後釋放；Boss保留44tick起手與起手霸體，刪除原蓄斬波次覆寫。
- 普通蓄刺可格擋、招架或一般墊步閃避；專用 `thrust` 仍為可踏刃的危險突刺。AI組合繼續引用 `charged`，不另建策略系統。奧義 `cleave` 雙斷仍消耗5共鳴、兩波命中且每次命中清除50架勢點，保留不同用途。
- 手機跳躍鍵靠近左側移動區，按鍵採較簡短文字；沿用原有pointer與input bit路徑。具體配置由 [PLATFORM](../PLATFORM.md) 維護，不能因改版面而另造第二份輸入邏輯。
- 通訊版本升至5並拒絕4等舊版：相同 `charged` ID已改變命中、防禦與動畫語意，不能容許兩端各自套用不同規則。教學lesson ID／儲存鍵、Boss容量、PvP100／100／2與單檔發行方式不變。

## Alternatives

- 只放大蹬踏水平範圍：仍會遺失略早按下的第二跳，也無法改善剛結束橫掃的反制感；採短緩衝、有限收招容許與位移輔助。
- 自動蹬踏或任何狀態均可取消：會移除第二次按鍵的選擇，並讓攻擊／治療承諾失效；保留上升緣與既有行動門檻。
- 把長按直接改為危險 `thrust`：會改變普通長按攻擊的防守方式並混淆踏刃提示；保留普通 `pierce` 與專用危險突刺的區別。
- 同時刪除雙斷或重寫AI／輸入框架：玩家針對的是普通長按攻擊與手機操作；奧義和既有共用路徑仍有獨立用途。

## Consequences

蹬踏允許較早的輸入與較寬的相對位置，仍要求空中、有效橫掃、無平台阻隔與一次反制限制。這是有限容錯，不是一般二段跳或自動追敵；未命中的緩衝會自然失效。對手機按鍵距離和手感的改善仍需實際玩家與裝置回饋。

同一 `charged` ID對應新玩法，所以舊客戶端必須更新才能互連；不能僅因ID未改就宣稱相容。沒有runtime migration in progress，也沒有新增save schema或尚未接線的registry。

## Verification / Revisit trigger

回歸應涵蓋蓄刺長按／放開、單次命中、格擋／招架、Boss44tick起手、專用危險突刺；蹬踏12tick緩衝邊界、hitstop、收招容許、遠距離／高度拒絕、平台阻隔、行動鎖、防禦轉跳、落地後新招與同attack ID重播。共用resolver與教學需維持原有反制結果；瀏覽器應驗證手機跳躍位置、按鍵文字與雙指輸入。已執行結果統一見 [VALIDATION](../VALIDATION.md)，本ADR不把待跑檢查宣稱為通過。

若真實回饋顯示輔助跨越錯誤地形、取消承諾或自動反制，優先縮小相應條件並新增重現案例；只有第二份內容確實需要共用吸附能力時才抽象化。回退必須一併還原source、教學／顯示、協議與生成HTML，不能只恢復 `MOVES.charged` 數值。
